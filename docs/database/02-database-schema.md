# 2. Database Schema

**TEAM-APPROVED INITIAL DATABASE DESIGN – VERSION 1.0**

## Conventions

- PostgreSQL; UUID primary keys generated by the application or `gen_random_uuid()` default (choose one consistently in migrations).
- `timestamptz` for event timestamps; `date` for calendar-only dates.
- `numeric`, not floating-point types, for currency and measured decimal quantities.
- Currency is stored as an ISO 4217 code in rows containing monetary values.
- All tables include `id UUID PRIMARY KEY` unless a composite primary key is explicitly stated.
- `created_at timestamptz NOT NULL DEFAULT now()` is used where listed.
- Names are lowercase snake_case. SQL below is a logical schema specification; Sahil should implement it with SQLAlchemy 2.x and Alembic.

## Cross-row consistency requirements

The following cannot be safely enforced by simple single-column CHECK constraints. Enforce them in transactional service logic or with carefully designed composite foreign keys:

- `ENQUIRY.customer_id` must own `ENQUIRY.site_id`.
- `SITE_SURVEY.site_id` must match the site belonging to its enquiry.
- `QUOTATION.survey_id` must belong to `QUOTATION.enquiry_id`.
- `STOCK_RESERVATION.order_id` must match the order referenced by `order_line_id`; `product_id` must match that order line.
- `DISPATCH_ITEM.order_line_id`, when present, must belong to the same order as the dispatch and use the same product.
- `EQUIPMENT_UNIT.product_id` must match the product on its dispatch item.
- An equipment event's site and installation references must be logically consistent.
- A service ticket's customer must own its site, if a site is supplied.
